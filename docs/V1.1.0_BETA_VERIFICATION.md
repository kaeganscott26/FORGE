# FORGE 1.1.0-beta.1 Verification

This record distinguishes implemented behavior from release evidence. The beta is not verified until every required final-commit and public-artifact gate below has observed evidence.

## Implemented source scope

- root-first workspace discovery and structured missing-path recovery;
- GPT-5.6 Responses API tool routing and provider-neutral direct-response support;
- workspace-owned PTY input, exit rejection, and writable restart;
- blank-file editor activation, save/open/undo/redo shortcuts, safe CLI environment, and keyless loopback model tools;
- schema-v4 persistent tasks, steps, dependencies, checkpoints, artifacts, approvals, external references, events, reconciliation, UI, and handoffs;
- Beta-channel discovery and legacy Preview preference migration;
- clean, manifest-driven ARM64/universal packaging, installation, and serial upload.

## Required provenance equality

The final evidence must prove:

```text
local main
= origin/main
= v1.1.0-beta.1 tag target
= workflow head SHA
= packaged embedded commit
= installed embedded commit
```

The universal DMG, ZIP, blockmaps, and `beta-mac.yml` must match the public asset sizes and SHA-256 values. The installed executable must originate from `/Applications/FORGE.app/Contents/MacOS/FORGE`, and no other installation or mounted FORGE DMG may remain.

## Acceptance gates

- dependency install, typecheck, lint, complete tests, production build;
- ARM64 and universal package creation from the intended commit;
- manifest, ZIP, DMG, updater metadata, architecture, signing, and provenance inspection;
- packaged `file://` app.asar renderer with no localhost dependency;
- manual terminal `pwd`, explicit output, exit rejection, and restart input;
- packaged `New file` activation/save plus Command-key save/open/undo/redo behavior;
- packaged `codex` resolution/launch after exact Gatekeeper trust and keyless Ollama model/file-tool routing;
- GPT-5.6 tool request through `/v1/responses` plus direct non-tool response;
- Tier 0 success, Tier 1 approval, Tier 2 approval/rejection, and linked audit records;
- root-first scan and recoverable `ENOENT` behavior;
- persistent task survival across renderer reload, application restart, conversation switch, and originating-conversation deletion;
- no repeated verified step and cross-workspace isolation;
- annotated tag, workflow, release, remote hashes, public download, public installation, diagnostics, and updater checks.

## Current evidence boundary

The final implementation-branch source gate passed clean dependency installation, typecheck, lint, 25 test files / 95 tests, production build, and a zero-vulnerability production audit. Earlier packaged probes cover the repair/task engine. A later isolated development-runtime probe created/opened/saved a blank file, handled a duplicate name without raw `EEXIST`, exercised undo/redo, ran Codex 0.147.0 and Ollama 0.32.1 in the PTY, listed and validated keyless Ollama models, and completed the provider-neutral money test: `llama3.2:3b` requested `file.read`, FORGE recorded exactly one automatic Tier 0 success, and the assistant returned the observed `draft-two-content` value. These probes are regression evidence, not final packaged beta release proof. Final merged-commit and public-artifact evidence will be recorded in the release task, audit log, build manifest, GitHub workflow, release metadata, and final handoff.

Signing and notarization are not configured in the repository. Unless the workflow demonstrates a trusted identity, the beta must be reported as ad-hoc signed/unsigned and manually installed.
