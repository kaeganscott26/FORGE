# 🗃️ FORGE v1.1.0-alpha.3 Verification Record

> **Historical release record.** This document preserves alpha.3 evidence and former Preview-channel terminology. It does not describe the supported beta.2 release; use the [documentation index](../../README.md) for current guidance.

## Immutable release boundary

- v1.0.1 remains GitHub Latest stable.
- `v1.1.0-alpha.1`, `v1.1.0-alpha.2`, and all of their published assets remain unchanged.
- No compatibility tag or duplicate release is created.
- Alpha.3 may be published only from an annotated tag on synchronized `main`, as a GitHub Pre-release.
- Every alpha.3 artifact must originate from the tag target and report that exact commit in diagnostics.

## Migration finding

Alpha.1 and alpha.2 used an incompatible mapping from FORGE's logical Preview setting to an Electron Updater provider channel. Those immutable clients cannot discover conventional `alpha`, `beta`, or `rc` tags. Alpha.2-to-alpha.3 therefore requires one manual installation and is not an automatic updater pass. The defect concerns discovery only; it does not invalidate the earlier apps, assets, tag provenance, or local SemVer comparison.

The discovery request is fixed to the FORGE GitHub repository, unauthenticated, limited to 50 releases, timed out after ten seconds, capped at one megabyte, schema validated, and restricted to this repository's HTTPS release metadata assets. Electron Updater is configured only after selection and the returned update version must equal the selected strictly newer version before download.

## Signing limitation

No Apple Developer ID or notarization credentials are configured. The package is expected to be ad-hoc signed with no TeamIdentifier. Update discovery and download can be verified, but unattended installation is not a trusted macOS update path.
